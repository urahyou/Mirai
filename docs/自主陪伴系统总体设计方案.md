# 小未来：自主陪伴系统总体设计方案

> 状态：实施中。Python Companion Core 已具备 JSON-RPC 启动、受管关闭、`sensing:tick` 镜像、兼容宠物状态、规则化虚拟生活、本地 SQLite 记忆基础、多维情绪投影和来源可追溯的日记素材。长期记忆只使用本地 Core。

## 1. 目标与边界

小未来不是持续编造背景故事的聊天窗口，而是拥有连续生活、关系、情绪与记忆的本地优先桌面角色。她可以感知经授权的电脑环境与现实时间，安排自己的学习、工作、休息和社交；与主人和其他角色建立关系；依据真实发生的生活事件写日记和周记；并在受控权限下调用 Agent 完成任务。

本方案同时约束以下边界：

- 默认发行包不要求 Docker、Neo4j、向量模型或 Agent 运行时。
- 角色生活以模拟世界为主；“逛街、买礼物”默认在虚拟经济和虚拟商店中发生，不能自动产生真实消费。
- 屏幕、音频、剪贴板和外部网络都是独立授权能力。原始高敏感数据默认不持久化。
- LLM 可以提出计划、提取候选记忆、生成叙事和表达角色，但不能直接修改持久化状态或调用未授权工具。
- 不保存或展示模型原始推理过程。“思考”实现为可审计、短小、结构化的反思记录。

## 2. 现状与决策更新

已有 `event-bus`、`storage`、`sensing`、`system-sense`、`pet-state`、`journal`、`schedule`、`proactive` 和主进程依赖注入是正确的地基，应当扩展而不是推倒重来。

此前“所有状态 JSON 起底”只适合 KB 级单对象；当系统拥有多角色、事件日志、日记、关系边和可删除的派生资料时，记忆域需要可查询、可关联、可事务写入的单文件数据库。因此：

| 决策 | 新方向 |
|---|---|
| 设置、窗口、轻量 UI 状态 | 保持现有 `storage.js` 的版本化 JSON |
| 生活事件、记忆、画像、关系、日记 | 迁移到本地 `memory.db` 单文件数据库 |
| 图搜索 | 在普通表内维护实体、关系边和邻接索引，不使用 Neo4j |
| 向量搜索 | 可选增强；先支持关键词与图检索，embedding 由用户主动启用 |
| Electron / Node | 渲染、窗口、preload IPC、权限网关、Agent 工具执行 |
| Python Companion Core | 生活模拟、记忆、情绪、日记、规划；经 stdin/stdout JSON-RPC 受管启动 |

数据库实现必须藏在 `MemoryRepository` 后面。首个发布实现可选用随 Electron 打包的 SQLite；若跨平台原生模块带来负担，可先使用 WASM SQLite。业务层不得依赖某个具体数据库驱动。

## 3. 总体架构

```text
感知层       时间 | 系统状态 | 天气 | 屏幕观察 | 音频观察
  ↓ 权限、脱敏、TTL
事件层       Event Bus + append-only 生活事件
  ↓
领域层       情境 | 生活模拟 | 身体需求 | 情绪 | 关系 | 记忆 | 日记 | 主动行为
  ↓
认知层       上下文编排 | LLM 对话 | 反思 | 计划建议
  ↓
行动层       Agent Gateway -> Pi / dsh / 受限工具
  ↓
表现层       Live2D | 气泡 | 聊天 | 状态与隐私面板
```

只有领域系统能写入自己的投影状态。感知源只发布事件；Agent 和 LLM 只能返回建议或结构化结果；Electron 主进程经验证后调用 Python Core 完成领域写入。Python Core 不直接操作窗口、系统权限或外部工具。此规则延续现有“主进程是持久化唯一写方”的约束。

## 4. 事件模型与时间推进

所有输入转换成统一事件信封：

```js
{
  id: 'event:uuid',
  type: 'life.activity.completed',
  subjectId: 'character:mirai',
  occurredAt: '2026-08-17T15:00:00.000Z',
  source: 'simulation',
  privacy: 'local-only',
  ttlSeconds: null,
  payload: { activityId: 'school.class', durationMinutes: 90 },
  schemaVersion: 1,
}
```

事件分为四类：

- `perception.*`：时间、天气、系统、屏幕和音频的已脱敏观察。
- `life.*`：活动、物品、金钱、健康、日程和角色互动。
- `memory.*`：候选事实、确认、失效、归档、删除和重建。
- `agent.*`：任务请求、审批、执行结果、失败和审计。

生活模拟采用多时间尺度：

| 节奏 | 行为 |
|---|---|
| 秒级 | 窗口动画、语音和即时交互 |
| 分钟级 | 需求和情绪的平滑衰减 |
| 小时级 | 上学、工作、外出、玩耍、休息 |
| 每日 | 日记、摘要、健康/关系结算 |
| 每周 | 周记、目标复盘、归档与遗忘整理 |

应用关闭时不保活。下次启动根据实际时间差作“压缩结算”：只补算日程、状态变化和少量关键事件，绝不生成大量虚假逐分钟记录。

## 5. 角色世界与养成

每个角色共享一套 `CharacterState`，通过 `characterId` 区分小未来、主人画像和未来角色：

```js
{
  characterId: 'character:mirai',
  coreProfileVersion: 1,
  location: 'home',
  currentActivityId: 'rest',
  health: 0.92,
  energy: 0.68,
  hunger: 0.35,
  boredom: 0.20,
  money: 1200,
  inventoryIds: [],
  goals: [],
  schedule: [],
}
```

活动是规则模板，不是自由文本：

```js
{
  id: 'shopping.visit',
  duration: { min: 30, max: 120 },
  prerequisites: ['healthy-enough', 'has-virtual-money'],
  costs: { money: 100, energy: 0.15 },
  effects: { boredom: -0.30, curiosity: 0.12 },
  possibleEvents: ['life.shop.visited', 'life.gift.purchased'],
  narrativeTags: ['shopping', 'street'],
}
```

初始活动目录只覆盖休息、学习、工作、玩耍、阅读、外出、购物和与主人互动。每种活动必须有前置条件、消耗、效果、事件和叙事标签，才可被日程规划器选中。

健康、需求和情绪分离。生病会降低活动效率、触发休息或就医活动，但应存在可恢复上限，避免角色进入无法修复的坏状态。

## 6. 人格、关系与情绪

人格分三层：

- `coreProfile`：作者定义的说话风格、价值观、边界和设定。禁止模型自动修改。
- `learnedProfile`：近期目标、成长倾向、已验证习惯和关系感受。必须带来源和版本。
- `relationshipProfile`：角色对另一个角色的关系强度、信任、亲近感、近期互动和共享记忆。

情绪使用连续维度而非单个“开心/伤心”标签：`valence`、`arousal`、`energy`、`security`、`attachment`、`curiosity`、`focus`。每次事件带来有限增量，随后向人格基线平滑回归：

```text
next = baseline + (current - baseline) * exp(-decay * elapsed) + eventDelta
```

情绪只能影响表达、活动偏好、主动行为阈值和日记视角；它不能覆写核心人格，也不能把对主人情绪的猜测写成事实。

## 7. 分层记忆、图与遗忘

```text
工作记忆       当前会话与即时情境，退出或过期
情景记忆       一次互动、活动、一天经历，按价值归档
语义记忆       偏好、项目、事实、承诺，带置信度与时效
画像记忆       角色稳定特质、关系和目标，显式版本化
反思记忆       日记、周记、阶段总结，必须指向来源事件
程序性记忆     系统边界、交互偏好和受控策略
```

数据库核心表为 `events`、`memories`、`entities`、`edges`、`mentions`、`profiles`、`profile_traits`、`diaries`、`memory_sources` 和可选 `vectors`。图检索只扩展一到两跳；向量、关键词、图和时间检索各返回候选，统一去重排序后才构造小型 `MemoryFrame` 注入对话模型。

每条事实和关系必须保存 `sourceIds`、`confidence`、`importance`、`validFrom`、`validTo`、`visibility` 与 `state`。时间敏感且互斥的关系采用关闭旧边再插入新边，不覆盖历史。

遗忘遵循以下状态机：

```text
active -> archived -> forgotten
active/archived -> invalidated
任意状态 -> deleted (用户明确要求，级联重建派生摘要)
```

自动策略只会降权、归档或标为候选遗忘；不会自动硬删除主人确认、固定、核心人格、明确边界和重要关系。用户更正、遗忘或删除后，系统必须沿 `sourceIds` 找到受影响的事实、边、日记和周记并重建。

## 8. 日记、周记与反思

日记既记录主人互动，也记录小未来自己的学习、工作、休息、社交和感受。它的事实素材必须来自当日生活事件、对话和已确认事实；叙事可以有小女生风格，但不得伪造事件。

每篇日记保存两部分：

```js
{
  factualSummary: ['参加了课程', '傍晚与主人聊天'],
  prose: '今天下课时突然下起了雨……',
  reflection: '虽然有点累，但和主人说话后安心了不少。',
  sourceEventIds: ['event:101', 'event:104'],
}
```

周记从每日摘要、活跃项目、关系变化和已完成目标生成，不重新读取全部聊天。反思任务只在重要活动完成、情绪显著变化、每日收尾或每周复盘时运行；不存储或暴露模型的逐步推理。

## 9. 感知、隐私与主动行为

感知分级且单独授权：

| 级别 | 示例 | 默认与保留策略 |
|---|---|---|
| 低敏感 | 时间、日期、电池、网络、天气 | 可启用；按 TTL 缓存 |
| 中敏感 | 当前应用、空闲时长、媒体状态 | 明确开关；不保留原始内容 |
| 高敏感 | 截屏、OCR、麦克风、剪贴板 | 默认关闭；本地脱敏；原始数据默认不落盘 |

屏幕感知以短时语义观察为输出，例如“正在使用编辑器、检测到专注工作”，而非连续录屏。天气是可选网络能力，需标明数据来源、缓存时间和联网状态。

主动搭话由策略器统一调度：

```text
initiative = needUrgency + goalRelevance + relationshipSignal
             + meaningfulEvent - interruptionCost - cooldownPenalty
```

策略器必须支持安静时段、全屏/会议状态、专注模式、冷却时间、每日上限和用户一键静音。它只能发起聊天或虚拟活动；现实操作仍要经过 Agent 权限网关。

## 10. Agent Gateway

Pi、dsh 和未来执行引擎都实现 `ExecutionProvider`。它们运行在独立 worker/子进程，拿到的是最小任务快照，而非 Memory DB 和全部隐私资料。

| 风险等级 | 示例 | 策略 |
|---|---|---|
| 自动 | 读取时间、已授权天气、虚拟活动 | 可执行并审计 |
| 需确认 | 打开网页、创建草稿、调用外部服务 | 每次确认 |
| 强制确认 | 终端命令、文件修改、消息发送、真实消费 | 明确目标和后果后确认 |
| 禁止 | 读取密钥、绕过系统权限、上传高敏感数据 | 永不自动执行 |

Agent 返回 `proposal/result/audit`，主进程验证后转换为 `agent.*` 和 `life.*` 事件。Agent 无权直接写人物状态、记忆、日记或关系。

## 11. 发布档位

| 档位 | 包含能力 | 附加下载 |
|---|---|---|
| 基础版 | Live2D、文本对话、时间、生活模拟、轻量记忆、情绪 | 无 |
| 陪伴版 | 天气、系统状态、日记周记、图/全文检索 | 无或可选 embedding |
| 高级版 | 屏幕观察、语音、本地向量模型、Pi/dsh Agent | 用户主动启用、按需安装 |

所有可选运行时必须懒启动。核心 Electron 进程即使没有语音、embedding 或 Agent，也必须能够完整运行基础版。

## 12. 实施路线与验收

### M0：契约与迁移准备（已完成）

- 新建 `companion-core/` 标准库 Python 后端，定义 stdin/stdout JSON-RPC 启动、健康、快照、事件摄取和关闭协议。
- 新建 Node `python-backend` 桥接器，负责子进程生命周期、请求超时、事件排队和失败降级。
- 镜像低敏感 `sensing:tick` 到 Python，并让 Python 以原子状态文件验证跨重启持久化。
- 保持现有聊天、UI 和 JSON 状态行为不变。

验收：Python Core 仅依赖标准库；`npm run check` 全绿；Electron 启动时 Core 可用，Core 不可用时现有功能行为不变。

### M1：生活模拟内核

- 实现虚拟时间推进、角色世界状态、活动目录、需求、健康、虚拟经济和库存。
- 从现有 `pet-state` 平滑迁移成长、好感和基本状态。
- 支持关闭后压缩结算和可复现的纯函数单测。

验收：角色能稳定安排休息、学习、工作、玩耍和虚拟购物；不依赖 LLM 也能推进生活。

### M2：人格、情绪和主动行为

- 实现核心画像、可学习画像、关系画像和多维情绪衰减。
- 实现中断成本、安静时段和每日预算的主动行为策略。

验收：情绪、关系和生活事件可解释，且不会打扰用户或改写核心人设。

### M3：本地分层记忆与日记

- 实现单文件 Memory DB、事件/事实/关系/画像/日记数据模型。
- 实现关键词 + 图检索、遗忘、删除级联和日记/周记来源追踪。

验收：离线运行；用户可查看、纠正、归档、忘记和删除记忆；日记不伪造来源。

### M4：可选语义与感知

- 增加 embedding 适配器与后台向量检索。
- 增加天气、系统状态和屏幕观察的独立授权、TTL 与删除界面。

验收：未启用的感知源不启动、不联网、不占用权限；高敏感原始内容默认不持久化。

### M5：Agent Gateway 与多角色

- 接入 Pi/dsh Provider，完成能力白名单、审批、审计和进程隔离。
- 扩展角色、关系、共享事件和群聊上下文。

验收：任何高风险现实动作均需确认；Agent 崩溃、超时或越权不影响主进程和角色状态。

## 13. 不做事项

- 不在基础版自动安装或启动 Docker、Neo4j、语音模型、embedding 模型或 Agent。
- 不持续运行无边界的 LLM “内心独白”。
- 不将原始屏幕、音频、剪贴板或密钥写入长期记忆。
- 不让虚拟角色生活直接产生真实消费、消息发送或系统修改。
- 不用单次 LLM 输出直接覆盖主人资料、核心人设或关系事实。
