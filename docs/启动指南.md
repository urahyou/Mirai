# 🐾 小未来 (Mirai) 启动指南

Electron 桌面桌宠「小未来」——类似伪春菜的透明悬浮桌面角色。由本地 Live2D 渲染，对话走 LLM，长期记忆用 Graphiti（Neo4j + 本地 embedding），语音由独立的 Python sidecar 提供。

---

## 一、整体架构

```
┌─────────────────────────────────────────────┐
│  Electron 主进程 (src/main/main.js)         │
│    ├─ 窗口 / IPC / 对话调度 / Provider 状态  │
│    ├─ 语音桥 (voice-bridge → ws:8765)       │
│    └─ Graphiti 桥 (graphiti-memory → :8766) │
├──────────┬──────────────────────┬───────────┤
│ 语音侧车  │     Graphiti 侧车    │  Neo4j    │
│ voice-    │  graphiti-sidecar/  │  docker   │
│ sidecar/  │  server.py (8766)   │  (7687)   │
│ (8765)    │  └─ LLM 抽取        │           │
│ └─ASR/VAD │  └─ Embedding(Ollama)│           │
│ └─TTS     │                     │           │
└──────────┴──────────────────────┴───────────┘
   本地 mirai_voice venv           本地 Ollama
```

**端口约定**

| 端口 | 服务 | 说明 |
|------|------|------|
| `8766` | Graphiti sidecar | 长期记忆 |
| `8765` | 语音 sidecar | ASR/VAD/TTS |
| `7474/7687` | Neo4j | HTTP / Bolt |
| `11434` | Ollama | 本地 LLM + embedding |

## 二、前置环境要求

| 依赖 | 版本/说明 | 校验命令 |
|------|-----------|----------|
| Node.js | v20（brew `node@20`） | `node -v` |
| Docker | 需 daemon 运行 | `docker info` |
| Ollama | 本地大模型运行时 | `ollama --version` |
| Graphiti venv | `graphiti-sidecar/.venv` | 见下 |
| voice-sidecar venv | `voice-sidecar/.venv`（语音用，本地 mirai_voice 内核，不再依赖 warashi） | 见下 |

> ⚠️ **Node 版本陷阱**：Electron 43.3.0 的下载工具 `@electron/get@5` 需要 Node ≥22，但本项目在 brew `node@20` 下安装。若 `npm start` 报 `ENOENT`/闪退，通常是 `node_modules/electron/dist` 缺失，需手动补二进制（`path.txt` 内容为 `Electron.app/Contents/MacOS/Electron`）。当前机器已正常，勿随意升级 Node。

## 四、配置 `.env` 关键项

### 对话 Provider

```dotenv
MIRAI_PROVIDER_CHATANYWHERE_API_KEY=你的Key    # 实际键名以应用面板/llm-providers.json 为准
MIRAI_PROVIDER_DEEPSEEK_API_KEY=
MIRAI_PROVIDER_OLLAMA_MAC_API_KEY=
```

> Provider 的出厂模板在 `src/core/llm-providers.json`，实际配置写入 Electron `userData/llm-providers.runtime.json`，Key 只从根目录 `.env` 读取。

### Graphiti（长期记忆）

```dotenv
GRAPHITI_ENABLED=true
GRAPHITI_BASE_URL=http://127.0.0.1:8766
GRAPHITI_GROUP_ID=mirai-owner
GRAPHITI_NEO4J_URI=bolt://127.0.0.1:7687
GRAPHITI_NEO4J_USER=neo4j
GRAPHITI_NEO4J_PASSWORD=mirai-dev-password
GRAPHITI_NEO4J_DATABASE=neo4j
# Graphiti 的 LLM（负责实体/关系抽取），必须支持稳定 JSON 输出
GRAPHITI_LLM_BASE_URL=https://api.chatanywhere.tech/v1
GRAPHITI_LLM_API_KEY=你的Key
GRAPHITI_LLM_MODEL=gpt-5.4-nano
GRAPHITI_LLM_MAX_TOKENS=4096
GRAPHITI_OLLAMA_THINK=false
GRAPHITI_EPISODE_TIMEOUT=300
GRAPHITI_SEARCH_TIMEOUT=60
# Embedding 用本地 Ollama，别浪费云端配额
GRAPHITI_EMBED_BASE_URL=http://127.0.0.1:11434/v1
GRAPHITI_EMBED_API_KEY=
GRAPHITI_EMBED_MODEL=bge-m3:latest
```

### 语音（可选）

```dotenv
# 默认 edge-tts（需联网）；要本地音色克隆改 gpt-sovits（参考 .env.example 注释）
SIDECAR_TTS_ENGINE=edge
```

## 五、按场景启动

### ⭐ 一键启动（推荐，全功能）

```bash
npm run start:all
```

自动完成：1) 确保 Neo4j 容器运行（不存在则创建）；2) 启动 Graphiti 记忆侧车（8766）；3) 若 `.env` 配置 `SIDECAR_TTS_ENGINE=gpt-sovits` 则自动拉起 GPT-SoVITS 服务（9880，已运行则复用）；4) 启动小未来桌宠本体（语音侧车 8765 由本体自动拉起）。退出时按 `Ctrl+C` 一并清理子进程。

> ⚠️ **Graphiti 是懒加载**：侧车起后 `health` 显示 `idle` 是正常的，收到第一次 `/episode` 或 `/search` 才真正初始化（约 20–50 秒）变为 `ready`。

### 场景 A：纯本地桌面（无记忆、无语音）

```bash
npm start
```

### 场景 B：仅记忆链路（手动分步）

```bash
# 终端 1：Neo4j
docker start mirai-neo4j     # 若容器已存在；不存在则用下方创建命令
# docker run -d --name mirai-neo4j -p 7474:7474 -p 7687:7687 \
#   -e NEO4J_AUTH=neo4j/mirai-dev-password neo4j:latest
# 终端 2：Graphiti 记忆侧车
npm run start:graphiti
# 终端 3：桌宠本体
npm start
```

### 场景 C：带语音（GPT-SoVITS）

```bash
npm run start:voice          # 自动拉起 GPT-SoVITS 并等就绪，再启动小未来
```

### 开发调试（打印渲染进程 console、开 DevTools）

```bash
npm run dev
```

```bash
# 停 Graphiti sidecar（其所在终端 Ctrl+C，或）：
pkill -f 'graphiti-sidecar/server.py'
# 停语音 sidecar：

```

> 语音 sidecar 由 Electron 主进程 spawn，关闭本体时通常一并退出；若残留可 `pkill -f sidecar_server.py`。

## 八、常见问题 (FAQ)

**1. `[Graphiti] add skipped: Graphiti sidecar HTTP 503` / `Rate limit exceeded`**
- Graphiti 的 LLM（如 ChatAnywhere）限流或响应慢。episode 内部多次抽取，最容易撞限流。
- 换新 Key 后**必须重启 sidecar**（sidecar 启动时才读取 `.env`）：
  ```bash
  pkill -f 'graphiti-sidecar/server.py'
  npm run start:graphiti
  ```

**2. `health` 一直 `idle`**
- 正常。Graphiti 是懒加载，发一次 `/search` 或 `/episode` 触发初始化后才 `ready`。

**3. episode 显示 `Request timed out`**
- 大多因云端模型慢或限流。已把 `GRAPHITI_EPISODE_TIMEOUT` 调大到 300 秒，并提高 `LLM_MAX_TOKENS`。若仍超时，考虑切换 `GRAPHITI_LLM_*` 到本地 Ollama（如 `qwen3:8b`）。

**4. 本地模型（如 `gemma4:e4b-mlx`）回到空回复**
- 某些本地模型会返回 reasoning 字段、`content` 为空并 `finish_reason:"length"`。不建议作为聊天兜底；可考虑 `qwen3:8b`。

**5. Graphiti 数据库已有很多旧测试分组**
- 只清理测试分组、保留 `mirai-owner`：
  ```cypher
  MATCH (n) WHERE n.group_id IN ['mirai-gpt54nano-test','mirai-luna-test','mirai-model-test'] DETACH DELETE n;
  ```

**6. ChatGPT/ChatAnywhere 模型在 `/models` 列表里但调用 429**
- 429 = 限流（免费额度耗尽或过频）。换新 Key，或改用一个稳定模型（本项目已实测 `gpt-5.4-nano` 可用）。

**7. macOS Gatekeeper「包含恶意软件」SIGKILL**
- 旧版 Electron 公证被吊销所致。当前 Electron 43.3.0 正常，若再遇是二进制下载不完整，非代码问题，重装 `node_modules/electron` 即可。

## 九、Prompt 管理说明

Prompt 正文统一存放在 `src/prompts/*.md`（每类一个文件），由 `src/core/prompts.js` 加载并替换变量：

```text
src/prompts/
├── chat.md            # 普通多轮聊天（{{personality}} {{memory_context}}）
├── pet-line-click.md  # 点击回应（{{personality}}）
└── translation.md     # 语音翻译（{{language}}）
```

修改语气/规则直接编辑对应 `.md`，无需改代码。Graphiti 的实体抽取 Prompt 由第三方 `graphiti-core` 内部维护，不在项目内管理。
